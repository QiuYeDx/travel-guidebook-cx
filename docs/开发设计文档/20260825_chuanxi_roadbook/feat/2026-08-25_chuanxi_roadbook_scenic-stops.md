# 主线 A 沿途观景点与观景走廊

## 背景

团队确认采用主线 A，但需要在讨论期和旅行中看到沿途适合拍照的观景台、停车点和无名景观路段。
原设计只有城市节点、每日路线和导航深链，无法表达“景色值得看，但这里不能停车”这一关键区别。

## 设计缺口

- 单一地图图钉会把连续河谷、草甸和山路错误压缩成一个坐标。
- 搜索平台中的同名地点可能是山峰、景区入口或反方向停车区，不能直接当停车入口。
- 国庆期间停车容量、临时管制和进出方向会变化，静态“可停车”结论存在安全风险。
- D3、D5 等长驾驶日若不限制停靠数量，路线很容易因拍照失控。

## 目标行为

1. `/scenic` 按 D1-D9 的实际行驶顺序展示观景路线带。
2. 已命名且完成核准的停靠点使用 `Viewpoint`；无唯一坐标的风景使用 `ScenicCorridor`。
3. 每项明确显示 P0 / P1 / P2 / 禁止停车、优先级、方向、复核状态、拍摄主题和停留预算。
4. `P2`、禁止停车、景交和步行点不出现社会车辆停车导航。
5. D3 最多停 4 次；D5 只从 D3 未完成项中补拍最多 2 个，不复制一套返程图钉。
6. 行中模式由副驾或乘客提前查看下一段，驾驶员不在行驶中操作页面。

## 实现摘要

- 攻略 v0.2 已建立稳定的 `VP-D*-*` / `SC-D*-*` 编号、类型、停车等级、每日预算和 D-7 复核清单。
- 结构化层采用 `Viewpoint`、`ScenicCorridor`、`GeoRef` 和 `ParkingProfile`，走廊只保存路线区间。
- 第一阶段使用可离线的路线带 + 列表；地图是后续渐进增强，并通过稳定 ID 与列表同步。
- 筛选维度为日程、优先级、停车等级、拍摄主题、行驶方向和复核状态。
